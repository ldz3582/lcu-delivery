## 1. 先选一条路线

| 路线 | 能干什么 | 需要什么 | 耗时 |
| --- | --- | --- | --- |
| **A. 体验版** | 自己 + 最多几十个朋友手机扫码能用 | 只要 AppID + 上传密钥；后端用局域网 IP 就够 | 1~2 小时 |
| **B. 正式上线** | 微信里搜得到、谁都能用、能收钱 | 营业执照 + 已备案域名 + 微信支付商户号 + 类目资质 | 2~6 周（备案最慢） |
| **C. 只管提审过、不收钱** | 审核能过、能发布，但支付走「到付」 | 营业执照 + 备案域名，改代码去掉在线支付 | 2~4 周 |

建议：**先走 A 把体验版跑通**（今天就能做完），再并行准备 B 的材料。

## 2. 路线 A：体验版（今天就能做完）

体验版是「上传 → 选为体验版本 → 手机扫码」，**不需要审核、不需要备案、不需要域名**。

### 2.1 确认 AppID

打开 <https://mp.weixin.qq.com> → 登录 → **开发管理 → 开发设置 → 开发者 ID**，把 AppID 抄出来。

和仓库里的不一样就跑一次接线（会同时校验 AppSecret）：

```bash
cd ~/Downloads/coderworks/外卖小程序/lcu-delivery
./ops/use-wechat.sh wx你的AppID 你的AppSecret
```

### 2.2 生成上传密钥 + 配 IP 白名单

后台同一页往下拉，找到 **「小程序代码上传」**：

1. 点「生成」→ 下载 `private.wxXXXX.key`（**只给一次**，别丢）
2. 同页「IP 白名单」→ 填本机公网 IP

```bash
curl -s https://api.ipify.org; echo      # 查本机公网 IP
```

> 不配白名单，上传必报 `40164`。

### 2.3 让手机能连到后端

两种办法，**推荐第二种**——第一种有两个坑：换 Wi-Fi 局域网 IP 就变（今天已经发生过一次，`10.81.213.138` → `10.145.64.245`），
而且别人必须跟你连同一个 Wi-Fi。

| 办法 | 命令 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 局域网 IP | `build http://<你的IP>:8080` | 零依赖 | 同 Wi-Fi 才行；IP 会变；每次变都要重新构建上传 |
| **内网穿透（推荐）** | `./ops/tunnel.sh start` | 公网 HTTPS，任何网络都能连 | 每次重启隧道地址会变，变了要重新构建上传 |

```bash
# 推荐：起隧道拿一个公网 HTTPS 地址
./ops/tunnel.sh start      # 打印 https://xxxx.trycloudflare.com
./ops/tunnel.sh rebuild    # 用这个地址重新构建小程序
./ops/tunnel.sh url        # 随时查当前地址
```

> 用的是 cloudflared 的免费快速隧道，**不需要注册账号**。地址是随机的，重启进程就换一个。

### 2.4 构建 + 出二维码

```bash
# 内网穿透版（推荐）
./ops/tunnel.sh rebuild

# 或者直接指定地址
./ops/publish-wechat.sh build https://xxxx.trycloudflare.com

# 出体验版二维码（需要上传密钥）
./ops/publish-wechat.sh preview ~/Downloads/private.wx6c9641b562b16363.key
```

脚本会自动做这些事：写 `.env.production` → 重新构建 → 检查产物里没有残留 `127.0.0.1` →
按地址是 http 还是 https 决定 `urlCheck` → 补 `libVersion` → **重新生成 `project.private.config.json`**
（uni build 会清空 dist，不重写这一份，开发者工具就会拿旧的「校验合法域名」设置把请求全拦掉）。

产物二维码在 `apps/lcu-mobile/dist/preview.jpg`（这是**预览二维码**：25 分钟失效，只能自己/项目成员扫；要给体验成员看，走 2.6 上传后下载体验版二维码）。

### 2.5 手机上打开，并关掉域名校验

1. 手机微信扫码 → 打开小程序
2. 右上角 **「…」 → 打开调试** → 小程序会自动重启
3. 这时候 `http://192.168.1.10:8080` 才不会被拦

> 这一步只有开发版/体验版能做，**正式版没有这个开关**，所以路线 B 必须上 HTTPS 域名。

### 2.6 或者走「上传 → 选为体验版」这条路（推荐，更稳）

```bash
./ops/publish-wechat.sh upload ~/Downloads/private.wx6c9641b562b16363.key 1.0.0 "内测第一版"
```

然后到后台：**管理 → 版本管理 → 开发版本 → 选为体验版本**，再在 **用户身份 → 成员管理 → 体验成员** 里加人。

**体验版二维码有效期 7 天**（2025 年底新规），过期回后台重新下载即可，体验版本身不会消失。
注意：上面 2.4 产出的 `preview.jpg` 是**预览二维码**（25 分钟失效、默认只有开发者能扫），**不是**体验版二维码，别拿它发人。

拉人、转发文案、打不开的排查，见 `docs/体验版内测邀请.md`。

### 2.7 别人能不能登录？（体验版的三道门）

「别人能用」要同时满足三件事，缺一件就打不开：

| 门 | 要求 | 说明 |
| --- | --- | --- |
| ① 成员资格 | 对方微信号被加进 **成员管理 → 体验成员** | **个人主体上限 15 人**，企业/已认证非个人主体 90 人 |
| ② 网络可达 | 用内网穿透就没限制；用局域网 IP 就得同一 Wi-Fi | `./ops/tunnel.sh start` 拿公网地址，谁都能连 |
| ③ 跳过域名校验 | 对方在自己手机上：小程序右上角「…」→ **打开调试** → 小程序自动重启 | 后端域名没备案、也没加进「服务器域名」白名单，不打开调试会报「不在以下 request 合法域名列表中」 |

三道门都过了，登录本身还有分支：

| 登录方式 | 现在能用吗 | 原因 |
| --- | --- | --- |
| **学号 / 工号登录** | ✅ 能 | 任填 6~20 位字母数字，首次登录自动注册；依赖 `APP_MOCK_LOGIN=true`（dev profile 默认开） |
| 微信一键登录 | ❌ 不能 | `ops/.env` 里 `WX_USER_APPID` / `WX_USER_SECRET` 是空的，后端会报「未配置小程序 AppID/AppSecret」 |
| 商家 / 骑手演示账号 | ⚠️ 看环境 | 只在 `mock-login=true` 时列表才有数据 |

> 要开微信登录：后台拿 AppSecret，跑 `./ops/use-wechat.sh wx你的AppID 你的AppSecret`，重启后端。
> 注意 `mock-login` 和生产是互斥的——开了微信登录、又关掉 mock-login，学号登录就一起没了。

### 2.8 没装 Docker 怎么起后端

`ops/dev.sh` 依赖 docker compose。本机装了 Homebrew 的话用这个，它会起 brew 的 MySQL 8.4（**挪到 3307**，
避开系统里已有的 3306）和 Redis，建库导数据，再拉后端：

```bash
./ops/dev-local.sh          # 启动（幂等）
./ops/dev-local.sh status   # 看 MySQL / Redis / 后端 三个灯
./ops/dev-local.sh stop     # 只停后端
```

## 3. 路线 B：正式上线

按顺序做，前一步不通别做下一步。

### 3.1 后端上公网

现在后端只在本机能跑（`ops/dev.sh` 起 MySQL/Redis + Spring Boot）。上线要：

```bash
# 打包
cd server && ../../tools/apache-maven-3.9.9/bin/mvn -DskipTests package
# 产物 target/lcu-delivery-*.jar，用 prod profile 启动
java -jar lcu-delivery.jar --spring.profiles.active=prod
```

- 服务器：1 核 2G 起步，装 JDK 21 + MySQL 8 + Redis 7（MinIO 可换云 OSS）
- 必须 `--spring.profiles.active=prod`，它会把 `mock-login` / `mock-pay` 关掉
- 上传目录 `ops/uploads` 要挂持久盘，或者配 `OSS_*` 走对象存储

### 3.2 域名 + 备案 + HTTPS（最慢的一步）

| 步骤 | 说明 | 周期 |
| --- | --- | --- |
| 买域名 | 腾讯云/阿里云，`.com` `.cn` 都行 | 即时 |
| ICP 备案 | 要营业执照或身份证，云厂商代备案 | **1~20 个工作日** |
| HTTPS 证书 | 云厂商免费 DV 证书就够 | 即时 |
| 解析 `api.你的域名.com` | A 记录指向服务器 | 即时（生效几分钟） |

微信小程序**不允许请求 IP**，必须已备案域名 + HTTPS。

### 3.3 微信后台配置（六件套，脚本做不了）

| # | 位置 | 填什么 |
| --- | --- | --- |
| 1 | 开发管理 → 开发设置 → 服务器域名 | `request` / `uploadFile` / `downloadFile` 都填 `https://api.你的域名.com`（每月只能改 5 次） |
| 2 | 开发管理 → 接口设置 | 开通「地理位置」（`getLocation` / `chooseLocation` 需要） |
| 3 | 设置 → 服务内容声明 → 用户隐私保护指引 | 勾选 **位置信息、相册（拍照上传）、剪贴板**（地址粘贴会读剪贴板） |
| 4 | 设置 → 基本设置 → 服务类目 | 餐饮服务类（要《食品经营许可证》或小餐饮登记证） |
| 5 | 设置 → 基本设置 → 小程序备案 | 2023-09 起强制，未备案不能发布 |
| 6 | 设置 → 微信认证 | 300 元/年，个体工商户/企业；**个人主体不能选外卖类目、不能开支付** |

### 3.4 构建并上传

```bash
./ops/publish-wechat.sh upload ~/private.wx6c9641b562b16363.key 1.0.0 "首个正式版本"
```

脚本会拦住三类常见事故：产物里残留 `127.0.0.1`、主包超 2MB、`urlCheck` 没关掉。

### 3.5 提审

后台 **管理 → 版本管理 → 开发版本 → 提交审核**。注意：

- **测试账号必填**。线上 `mock-login=false`，演示账号表是空的，审核员点「商家 / 骑手」会进不去
- 提审说明里写清楚：本版本开放的是**用户端**（浏览店铺 → 加购 → 下单 → 看订单）；商家端/骑手端是运营侧角色，需入驻审核，审核期间可用 XXX 账号
- 类目、名称、简介要和内容一致，别写「校园外卖平台」又不给校园场景

### 3.6 发布

审核通过（一般 1~3 个工作日）→ 后台点「发布」→ 全量上线。之后每次更新重复 3.4~3.6。

## 4. 支付怎么办（当前最大的坑）

代码现状：`application-prod.yml` 里 `mock-pay: false` → Spring 装配 `WechatPayGateway` → 它的 `prepay()` 第一行就抛异常：

```
微信支付通道尚未接入：请按 WechatPayGateway 注释完成 SDK 接入后重试
```

也就是说**线上环境用户下完单就卡在待支付，商家永远收不到单**。审核员实测会直接拒（「核心功能不可用」）。

三个选项：

### 方案 1：接真微信支付（唯一能真收钱的路）

前置：个体工商户/企业主体 + 已认证小程序 + 微信支付商户号 + 对公账户（个体户可绑法人卡）

要做的事：

1. 商户平台申请「JSAPI 支付」，拿到 `mchid`、APIv3 密钥、商户证书 `apiclient_key.pem`
2. 商户平台 **产品中心 → AppID 账号管理** 绑定小程序 AppID
3. 填 `ops/.env` 的 `WXPAY_*` 七项
4. 补 `WechatPayGateway.prepay()` 的真实实现（下单 `/v3/pay/transactions/jsapi` → 返回 `timeStamp/nonceStr/package/signType/paySign`）
5. 补 `notify()` 的 APIv3 解密与验签
6. 前端 `cart.vue` / `order/detail.vue` 把 `api.mockPay()` 换成 `uni.requestPayment()`

工作量：后端 300 行左右 + 前端 20 行，主要时间花在证书和回调域名的联调上。

### 方案 2：改成「到付 / 校园卡付款」，先上线不收钱（审核最容易过）

改动很小：下单后订单直接从 `UNPAID` 进 `WAIT_ACCEPT`，前端去掉支付按钮。

- 好处：不需要商户号、不需要企业主体之外的东西，审核不会因为支付卡住
- 坏处：线上收不到钱，得线下收

**如果目标是「先在学校里真跑起来」，这是性价比最高的路。**

### 方案 3：只发体验版，不发布

体验版不需要审核，支付走 mock 也没人管。适合内部验证产品。

## 5. 提审避坑（针对这个项目）

| 风险 | 为什么会被拒 | 怎么避 |
| --- | --- | --- |
| 下单后付不了款 | 线上支付是空壳 | 走方案 1 或 2 |
| 审核员进不去商家/骑手端 | 线上关了 mock 登录 | 提审说明写清范围，或给一个已审核通过的店铺账号 |
| 位置信息被拒 | 隐私指引没勾「位置」 | 后台「服务内容声明」补齐 |
| 读剪贴板被拒 | 地址编辑页有「粘贴」按钮 | 隐私指引勾「剪贴板」 |
| 类目不符 | 选了非餐饮类目 | 类目选餐饮服务，备好食品经营许可证 |
| 备案没做 | 未备案不能发布 | 提前 2~3 周启动备案 |
| 名称/简介夸大 | 「全国」「平台」等词 | 写「聊城大学校园外卖配送」这种具体描述 |

## 7. 错误码对照

| 报错 | 含义 | 解决 |
| --- | --- | --- |
| `40164` | IP 不在白名单 | 后台「小程序代码上传 → IP 白名单」加本机公网 IP |
| `-1` / `system error` | 微信侧抖动 | 重试 |
| `invalid ip` | 同上 | 同上 |
| `40013` AppID 无效 | AppID 抄错或小程序注销 | 重新复制 |
| `40125` AppSecret 无效 | Secret 重置过 | 后台重置后跑 `use-wechat.sh` |
| 开发者工具报 `不在以下 request 合法域名列表中` | 生产构建连了没白名单的域名 | 后台配服务器域名，或本地勾「不校验合法域名」 |
| 上传报 `代码包大小超过限制` | 主包 > 2MB | `du -sk dist/build/mp-weixin` 查，拆分包 |
| 提审报「缺少隐私保护指引」 | 后台没配 | 设置 → 服务内容声明 |
| `task type:upload exec error abort`（开发者工具 CLI） | CLI 上传被 IDE 秒拒，通常是 IDE 里项目窗口没编译完 / 开了多个窗口 | 直接在开发者工具里点右上角「上传」按钮，一样的效果，且不用配密钥 |

> **上传的两条路，任选一条：**
> - **GUI（最省事）**：开发者工具打开 `dist/build/mp-weixin` → 点「上传」→ 填版本号 → 后台「版本管理」里就能看到。**不需要上传密钥**。
> - **命令行（可进 CI）**：`./ops/publish-wechat.sh upload ~/private.xxx.key 1.0.0 "描述"`。需要后台生成上传密钥 + 配 IP 白名单。
